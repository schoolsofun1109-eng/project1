================================================================================
ROOT CAUSE ANALYSIS
================================================================================

The buffer naming fix in commit 66d0acd changes:
  OLD: all N-split iterations used "W_spad" (collision)
  NEW: N-split iterations use "W_0_spad", "W_1_spad", etc. (no collision)

HOWEVER, this fix only addresses buffer NAME aliasing, not deeper issues in:

1. N-SPLIT ITERATION COORDINATION
   - DMA transfer sequencing across N-tile iterations
   - Proper weight tile loading for each iteration
   - Correct DRAM addressing for split weight matrices

2. OUTPUT BUFFER ACCUMULATION
   - Pattern of zeros in last rows suggests output buffer not properly
     carrying values across N-split iterations
   - Possible issue with OMEM read-after-write or accumulation semantics

3. WEIGHT MATRIX ADDRESSING
   - N-split requires loading different weight tiles for each iteration
   - Test 1 error pattern (first/last cols correct, middle wrong) suggests
     only first and last weight tiles are correctly loaded
   - Middle weight tiles may be overwritten or misaddressed

4. TILE ITERATION SEMANTICS
   - Square matrices work (single N-iteration)
   - Rectangular matrices fail (multiple N-iterations)
   - This strongly indicates N-split iteration loop has bugs in either:
     a) MLIR code generation for nested DMA loops
     b) Variable linking between iterations
     c) Buffer offset calculations for split tiles
