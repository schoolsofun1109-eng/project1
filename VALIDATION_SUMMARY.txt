ROOT CAUSE ANALYSIS
================================================================================

Key Observation: Tests ONLY pass when M = N (square matrices)

Tile Stride Fix Analysis:
   The fix updates stride formulas from:
   - X: [TILE_M, 1] → [TILE_K, 1]  (mathematically correct)
   - W: [TILE_K, 1] → [TILE_N, 1]  (mathematically correct)
   - Y: [TILE_M, 1] → [TILE_N, 1]  (mathematically correct)

   Why it passes for square matrices:
   - When M = N: TILE_M = TILE_N
   - So [TILE_K, 1] and [TILE_M, 1] give same result
   - Fix works by accident for square case

   Why it fails for rectangular:
   - When M ≠ N: TILE_M ≠ TILE_N
   - The stride fix is necessary but NOT sufficient
   - Root cause is elsewhere in the pipeline

Error Pattern in Rectangular Tests:
   - Some tiles compute correctly
   - Some tiles have all zeros
   - Some tiles have completely wrong values
   - Indicates: SRAM buffer allocation or DMA addressing issue
   - NOT: tile stride definition issue

CONCLUSION
================================================================================

The tile stride fix (27ede7a) is CORRECT but INCOMPLETE.

The fix alone does NOT solve rectangular matmul failures because:

1. Tile stride definition [TILE_K,1], [TILE_N,1] is mathematically correct
2. But the fix works for square matrices M=N only (coincidence)
3. The real issue is NOT in the stride formula itself
4. The real issue is in how strides are USED in:
   - DMA operation address calculation
   - SRAM buffer allocation for split iterations
   - N-split/M-split tile distribution
   - Vector lane mapping for non-square tiles
